## 1. 新制狀態機

三個部位狀態，數字為**弱勢股（被加碼那一邊）的權重**：

| 狀態 | 配置（弱勢股/強勢股） |
|---|---|
| 0級 | 50 / 50 |
| 1級 | 75 / 25 |
| 2級 | 100 / 0 |

`diff = dev_A - dev_B`，`dev_X = close_X / MA_X - 1`（沿用現行，未變）。
`diff > 0` → A 為強勢股（賣A買B）；`diff < 0` → B 為強勢股。

### 狀態轉移表

| 目前部位 | 漲破 T2 | 漲破 T1 | 跌破 T2 | 跌破 T1 | diff 變號 |
|---|---|---|---|---|---|
| **0級 50/50** | → 2級 | → 1級 | 不適用 | 不動 | 不動 |
| **1級 75/25** | → 2級 | 不動 | 不適用 | **不動** | → 0級 |
| **2級 100/0** | 不動 | 不適用 | **不動** | → 1級 | → 0級 |

兩個關鍵設計（與舊制、與作廢的區間機制都不同）：

- **T2 只當進場線，不當退場線。** 2級跌破 T2（例如 diff 由 8% 掉到 5%）
  維持 100/0 不動作。這消滅了門檻邊緣的來回換手。
- **減碼只有一次。** 2級跌破 T1 退到 1級；1級之後就黏著，只有 **變號** 才
  回到 0級 50/50。

「1級 + 跌破T2」與「2級 + 漲破T1」標為不適用是**邏輯上不可達**，不是設計
選擇：在1級時 diff 必定 ≤ T2（一旦漲破 T2 立刻變2級），故不可能從 T2 之上
跌破 T2。

### 參考實作（已驗證，回測用的就是這段）

因為狀態已決定，判斷可以純用當下的 `|diff|` 落點，不需要記錄穿越：

```python
BAND_W = {0: 0.50, 1: 0.75, 2: 1.00}   # 弱勢股權重

ad, sgn = abs(d), (1 if d > 0 else -1)
new_pos, new_side = pos, side
if pos != 0 and side != 0 and sgn != side:      # 變號
    new_pos, new_side = 0, 0
    if ad > T2:   new_pos, new_side = 2, sgn    # 同日立即再進場
    elif ad > T1: new_pos, new_side = 1, sgn
elif pos == 0:
    if ad > T2:   new_pos, new_side = 2, sgn
    elif ad > T1: new_pos, new_side = 1, sgn
elif pos == 1:
    if ad > T2:   new_pos = 2                   # 跌破T1 不動 (黏著)
elif pos == 2:
    if ad <= T1:  new_pos = 1                   # 跌破T2 不動

if (new_pos, new_side) != (pos, side):
    w = BAND_W[new_pos]
    tot = value_a + value_b
    target_a = tot*(1-w) if new_side > 0 else (tot*w if new_side < 0 else tot/2)
    # ... 調倉到 target_a（記得扣交易成本，見第3節）
    pos, side = new_pos, new_side
```

**變號當日的處理採「同日立即再進場」**（上面的 option b）：先概念上回到
50/50，再依當日 `|diff|` 直接進到對應級別，一天一筆交易完成。這與舊制的
「變號回流 + 當日觸發分級」寫在同一迴圈的行為一致。

## 2. ⚠️ 回測務必計入交易成本

**這是先前所有回測共同的缺陷，任何新回測都必須修正。** 不計成本會得到
完全相反的結論——先前那個作廢的可逆區間機制在零成本下六對有三對改善，
計入成本後六對全部退步。

台股實際費率（本專案採用的假設）：

| 項目 | 費率 | 收取時機 |
|---|---|---|
| 券商手續費 | 0.1425% × 0.2（2折） = **0.0285%** | 買、賣各收一次 |
| 證券交易稅 | **0.3%** | 只在賣出時收一次 |

搬動 M 元從一檔到另一檔的實際損耗：

```python
FEE, TAX = 0.001425 * 0.2, 0.003
LEAK = 1 - (1 - FEE - TAX) * (1 - FEE)     # = 0.3569%
# 賣出 M 元 -> 實收 M*(1-FEE-TAX) -> 買進後持有 M*(1-FEE-TAX)*(1-FEE)
```

實作時**對每次調倉的搬動金額 M 課 `M * LEAK`**，不是對總資產課費。
`turnover`（累計搬動金額 ÷ 起始資金）是成本的真正驅動因素，比交易次數更
重要——請一併記錄與顯示。

**尚未計入的成本**：滑價（買賣價差、衝擊成本，以及「用收盤價成交」在實務上
需掛收盤集合競價、無法保證成交在該價位）。目前回測假設訊號與成交都在
同一日收盤價，這點偏樂觀。

## 3. 對 API / 前端語意的影響

`compute_pair_signal()` 回傳欄位需調整：

- `sell_fraction` 已無意義 → 改為 `band_weights: [0.50, 0.75, 1.00]`。
- `is_open` → `pos > 0`。
- `entries_since_reset` / `tier_index` → 改為**當前級別**（0/1/2），不是
  累計觸發次數。
- `tier_marks[].fired` → 舊語意（本回合已觸發過）不適用。建議改為標示各
  級別的價格位移邊界，並標出當前所在級別。
- **門檻線需區分進場線與退場線**：T1 兩者皆是（進場+退場），T2 只有進場。
  2級時應顯示「跌到多少會退回1級」（即 T1 對應價位），**不是** T2。
- `reset_ab`（diff=0 的價格位移）仍有效，代表變號回到 50/50 的位置。

`PairStrategyShared.jsx` 的 `ThresholdBar` / `SignalRow` 為 v1/v2/lite 共用，
而 **v1 與 v2 仍是舊棘輪機制**，修改時不可破壞它們。建議以 `band_weights`
是否存在來分支，或把 lite 的呈現拆成獨立元件。

## 6. 已放棄的設計（勿重新實作）

**逐級可逆區間機制**：目標配置純由當前 `|diff|` 落點決定，每一條邊界（T1
與 T2）雙向都觸發，2→1→0 逐級退場。

零成本下六對有三對改善（1年勝率最多 +19p），但**計入成本後六對全部退步**
（IR -0.07 ~ -0.52，AI伺服器 End勝率從 93.6% 崩到 65.6%）。原因是換手暴增
2~3 倍：T1 邊界的來回穿越佔了 53% 的交易筆數，而 diff 有一半以上時間就在
T1 附近擺盪。記憶體雙雄五年累計換手達 225.7x，光成本就吃掉約 80% 的資本。

新制保留了「能部分減碼」的優點，但把它限制成一次、且退場線只用 T1，換手
只增加到 147.8x（相對舊制 92.5x），成本可控。
